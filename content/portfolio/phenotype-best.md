# 대표 프로젝트인 이유

## 가장 자신 있는 프로젝트로 꼽는 이유

디지털 피노타이핑 연구 플랫폼은 백엔드를 처음부터 끝까지 혼자 맡아 설계·구현·테스트·배포·운영까지 직접 책임진 프로젝트

- **백엔드 전담** - 도메인 설계, API, 스케줄러, 인증, 테스트 구조까지 백엔드 전체를 담당하고 어드민 프론트 일부와 배포 인프라도 맡음
- **실제 운영 중** - 연구 참가자의 스마트폰과 웨어러블에서 실데이터를 수집하며 운영 중
- **문제의 폭** - 대량 시계열 수집, 외부 API 동기화, 캐시 설계, 설문 회차 판정처럼 성격이 다른 문제를 한 프로젝트에서 직접 풀어냄

## 직접 풀어낸 핵심 문제

- **대량 시계열 수집** - 기기마다 끊임없이 쌓이는 이벤트를 TimescaleDB hypertable과 압축 정책으로 저장하고, bind 파라미터 상한을 넘지 않게 나눠 대량 INSERT
- **실패해도 스스로 복구되는 동기화** - Google Health 데이터를 증분 병합 대신 하루 단위로 통째로 받아 덮어써, 실패해도 다음 실행에서 저절로 복구
- **조합 폭발을 피한 캐시** - 타임라인 캐시를 레인 조합이 아닌 레인 하나 단위로 잡아, 새로 켠 레인만 계산
- **스토어 밖 앱 배포** - 스토어 정책상 배포할 수 없는 수집 앱을 위해 버전별 APK 보관, 고정 주소 QR, 매니페스트까지 명령 하나로 배포하는 경로 구축

## 오래 유지되는 구조

- **규칙을 도구로 강제** - 모듈 간 의존을 막고 흐름은 usecases 계층에서만 조합하도록 하고, 이 규칙을 import-linter·ruff로 CI에서 차단
- **테스트 3계층** - API 흐름(integration), 비즈니스 로직(services), 실제 TimescaleDB에서의 쿼리(repositories)로 나눠 검증
- **확장에 열린 설계** - 지표 정의를 DB에서 관리해 새 지표가 생겨도 클라이언트 수정 없이 서버 계산만 추가
